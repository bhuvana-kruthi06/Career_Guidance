# Remaining career tools — implementation status

## Implemented

- Replaced the old reflection-only signed-in interview screen with role/type/difficulty mock sessions, one-question-at-a-time answering, AI feedback through the existing backend provider, local feedback fallback, final readiness report, and per-user saved/resumable session history.
- Connected job-description matching to the saved profile, extracted resume skills, selected role requirements, and skill gap data. Analyses can be listed, opened, deleted, and their recommended learning tasks can be added idempotently to the roadmap.
- Completed owner-scoped application list/create/edit/delete/status APIs and a Kanban UI with drag/drop, status controls, search, filters, job details, follow-ups, and per-status analytics.
- Replaced dashboard sample application, interview, project, and roadmap values with data fetched from account APIs. Follow-up and roadmap tasks feed the upcoming list; interview readiness contributes to the readiness score.
- Kept guest interview reflection drafts and the existing three-step local roadmap available. Added request-body limits and per-IP rate limits for interview and mentor requests.
- Added API documentation in `docs/CAREER_TOOLS.md`; the existing V5 schema already provides `career_tool_records` and `job_applications`, so no database migration was needed.

## Privacy and limitations

Job-description matching is deterministic and runs locally; the pasted job text and profile-derived skills are not sent to an external provider. An attempted change to send them to the configured AI provider was rejected by automatic review because that would transmit user-provided and profile-derived data externally. Interview answer feedback may use the existing configured backend provider; without it, the local rubric explicitly says it cannot verify factual or technical correctness.
